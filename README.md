# MenuBar 菜单栏收纳

一个很小的 macOS 菜单栏收纳工具。菜单栏图标太多、被刘海挡住时，把不常用的收起来。

## 安装

```bash
./build.sh install     # 编译、安装到 /Applications 并启动
./build.sh             # 只编译，产物在 build.noindex/MenuBar.app
```

只需要 Xcode 命令行工具（`xcode-select --install`），不需要完整的 Xcode。支持 macOS 13 及以上，Apple 芯片和 Intel 通用。

## 使用

菜单栏右上角、控制中心旁边会出现一个箭头「›」。箭头左边的图标可以收起，箭头右边的图标一直显示。

### 找回看不到的图标

点箭头，菜单最上面会列出所有看不到的图标，包括被刘海挡住的和被收起的。点其中一项，就会打开那个图标自己的菜单。

如果列表底部显示「另有 N 个图标读不到是哪个 App 的」，说明系统知道那里还有被挡住的图标，但对应的 App 没有回应读取，所以列不出名字。下面一行会写出可能是哪个 App。最常见的原因是 App 运行期间程序文件被替换了（比如重新编译安装过），重启那个 App 就好。

接了外接显示器时，每块屏幕的菜单栏上都有一份图标，只有当前使用的那块屏幕（箭头所在的那排）上的图标会算进来。

### 在列表里调整顺序

列表从上到下，就是这些图标在菜单栏上从左到右的顺序。按住 ⌘ 上下拖动某一行，会出现一条蓝线标出插入位置，松手后菜单栏里的图标会跟着挪过去：

1. 菜单栏先展开，被收起的图标回到屏幕上。
2. 程序替你按住 ⌘ 把图标拖到新位置，期间鼠标会闪一下。
3. 菜单栏收起，核对顺序，然后重新打开列表，显示新的顺序。整个过程约 2 秒。

拖动时按 Esc 取消。两种情况会弹窗说明：

- **展开后仍然被刘海挡住的图标**：系统不允许拖动看不见的图标。可以在「系统设置 › 菜单栏」里关掉几个用不到的图标，腾出位置后再调整。
- **拖到紧挨刘海的位置**：菜单栏放不下时，macOS 会自己挑一些图标藏到刘海后面，被藏的不一定是最左边的。往这里挪，偶尔会落到隔壁位置，并被系统藏起来，没法再微调。

这个功能需要辅助功能权限。第一次启动时系统会弹窗询问，也可以手动打开：系统设置 › 隐私与安全性 › 辅助功能 › 打开 MenuBar。

> `build.sh` 第一次运行时会在 `.signing/` 里生成一个本地自签名证书，之后每次都用它签名。系统因此能认出重新编译后的还是同一个 App，辅助功能权限不会失效。证书存在独立的钥匙串文件里，不会动你的登录钥匙串。删掉 `.signing/` 会生成新证书，那时需要重新授权一次。

### 收起不常用的图标

| 操作 | 效果 |
| --- | --- |
| 点箭头 › 收起菜单栏 | 箭头左边的图标全部收起，给其他图标腾位置 |
| 按住 ⌘ 拖动箭头 | 把箭头放到常驻图标的左边 |
| 按住 ⌘ 拖动其他图标 | 拖到箭头左边会被收起，拖到箭头右边会一直显示 |
| ⌃⌥⌘B | 全局快捷键，收起 / 展开 |

### 设置

在箭头菜单的「设置」里：

- **左键点击箭头**：默认显示看不到的图标，也可以改成直接收起 / 展开。
- **自动收起**：展开后多久自动收起，默认 10 秒。鼠标停在菜单栏上或有菜单打开时会推迟。
- **启动时自动收起**
- **全局快捷键**
- **开机自动启动**：建议先把 App 放到「应用程序」文件夹再开启。

## URL Scheme

可以配合快捷指令、Raycast、Alfred 使用：

```bash
open "menubar://toggle"         # 切换
open "menubar://collapse"       # 收起
open "menubar://expand"         # 展开
open "menubar://open?app=微信"   # 打开指定图标的菜单，名字写一部分即可
open "menubar://menu"           # 打开看不到的图标列表，和点箭头一样
open "menubar://debug"          # 把当前状态和扫描到的图标写入 ~/Library/Logs/MenuBar.log
```

## 原理

- **收起**：收起时，在箭头左边紧贴着放一个看不见的分隔图标，宽度设成 10000，它左边的图标会被挤出屏幕。展开时把它从菜单栏拿掉，不占任何位置。这部分不需要任何权限。
- **只有一个箭头**：macOS 会把放不下的图标整个藏起来，所以箭头自己不能变宽，必须由另一个图标来撑开。你拖动箭头后，分隔图标不会自动跟过去，所以每次收起前程序都会检查，没贴住箭头就重新放一次。
- **看不到的图标**：通过辅助功能接口读取每个 App 的菜单栏图标和位置，再用系统窗口列表判断哪些没有显示在屏幕上。点击列表项时，用辅助功能接口替你「按下」那个图标。少数 App 读不到，列表底部会显示「另有 N 个图标读不到是哪个 App 的」。接了外接显示器时，系统在每块屏幕的菜单栏上各放一份图标窗口，只有箭头所在那一排是图标本身，其余是副本；同一排的窗口首尾相接，所以从箭头出发往两边连着找，就只会数到这一排。
- **调整顺序**：系统菜单自带的菜单项不能拖动，所以列表的每一行是自定义视图，自己处理高亮、单击和拖动。系统也没有提供改别的 App 图标位置的接口，只能像用户一样按住 ⌘ 拖动。所以程序先展开菜单栏，再模拟一次按住 ⌘ 的拖动：往左拖时停在目标图标的左半边，往右拖时停在它左边那个图标的右半边。拖完先收起再核对：展开时菜单栏放不下，系统会挑一些图标藏到刘海后面，被藏的不一定在最左边，展开时看到的顺序并不完整；收起后所有图标在屏幕外排成连续的一排，按系统窗口编号（图标挪动后不变）看两个图标是否挨着，不对就再拖，最多 3 次。

## 测试

```bash
Tests/system_test.sh            # 在真实菜单栏上把核心功能跑一遍，约 2 分钟
Tests/system_test.sh --rebuild  # 另外测试重新编译安装后布局和授权是否保持
```

测试会收起、展开菜单栏若干次，并短暂弹出测试图标、KeyDock 和 MenuBar 自己的菜单，结束后恢复为收起状态。运行期间不要碰鼠标和菜单栏。全局快捷键需要真实按键，脚本无法覆盖。

测试用到的调试命令：

```bash
open "menubar://debug?latency=1"                # 诊断信息里加上每个 App 的响应耗时
open "menubar://dismiss"                        # 有弹出菜单开着时发一个 Esc 关掉它
open "menubar://menu?close=3"                   # 打开列表，3 秒后自动关掉
open "menubar://testclick?item=ALPHA"           # 打开列表，模拟单击某一行
open "menubar://testreorder?item=A&before=B"    # 打开列表，模拟按住 ⌘ 把 A 拖到 B 前面；不带 before 表示拖到最后
                                                # 可加 hold=秒数（拖到位后停一会儿，方便截图）、reopen=秒数（调完重新打开列表）
open "menubar://drag?from=1100&to=1150"         # 在菜单栏上按住 ⌘ 从 x=1100 拖到 x=1150
```

菜单开着时 MenuBar 不处理 URL 命令，所以模拟操作都由 MenuBar 自己在后台线程发出鼠标事件，走的是和手动操作相同的流程。

## 恢复默认位置

```bash
defaults delete com.local.MenuBar
```

删除后重新启动 App，箭头会回到时钟旁边，使用说明也会再弹一次。

## 目录

```
Sources/              Swift 源码
  StatusBarController.swift   核心逻辑：收起展开、菜单、自动收起
  MenuBarScanner.swift        读取所有菜单栏图标，判断哪些看不到
  HiddenItemsList.swift       列表的每一行：高亮、单击打开、按住 ⌘ 拖动排序
  MenuBarMover.swift          模拟按住 ⌘ 拖动菜单栏图标
  HotKey.swift                全局快捷键
  LoginItem.swift             开机启动
  Prefs.swift                 设置项
Resources/Info.plist  App 配置（LSUIElement，不显示 Dock 图标）
Tools/make_icon.swift 生成 App 图标
Tests/                系统测试脚本、测试用的小 App 和窗口检查工具
build.sh              编译打包脚本
.signing/             本地签名证书（自动生成，不要分享）
```
